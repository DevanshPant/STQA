What the model does

Given a car's specifications — model year, maker, vehicle class, motor power and recharge time — the network predicts its energy efficiency in km per kWh. That number drives everything else on this site: cost per 100 km, trip costs and comparisons.

The project concept is battery thermal management, but this dataset has no temperature readings, so — exactly as in Experiments 2–7 — the models are trained on energy efficiency. The same pipeline would take temperature as the target once sensor data is available.

  3. Feature engineering: added Power rate = motor kW ÷ recharge hours (as in Exp 3).
  4. Encode: one-hot encoding of vehicle class and maker → {{ m.dataset.features }} input features.
  5. Split: {{ m.dataset.train }} cars for training, {{ m.dataset.test }} held back for testing (80 / 20, seed {{ m.hyperparameters.seed }}).
  6. Scale: StandardScaler on the 4 numeric columns; one-hot columns stay 0/1.

4. LSTM on the efficiency sequence (Exp 7)

Rows were ordered by model year and the LSTM learned to predict the next car's efficiency from the previous {{ m.lstm.look_back }}. Test MAE {{ "%.3f"|format(m.lstm.test.mae) }} km/kWh, R² {{ "%.3f"|format(m.lstm.test.r2) }}.

It does noticeably worse than the DNN because cars within the same year are in no real time order — the sequence carries little signal. An LSTM becomes the right choice with genuine time-series data, such as battery temperature logged every second.
